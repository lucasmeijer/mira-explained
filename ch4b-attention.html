Chapter 04b · a refresher, using MIRA's own tokens

How an attention block actually works

Chapter 04 showed where attention sits in MIRA. This page opens one attention layer and runs it step by step, with real arithmetic on real MIRA latent tokens. You'll see every matrix the layer builds, then how MIRA stacks the pieces into a full block: heads, grouped keys, rotary positions, the space/time reshaping trick, the gate and the MLP.

1 · The one-paragraph version

An attention layer takes a set of tokens and lets every token pull in information from the others, weighted by relevance. Each token is projected three ways: a query (what it is looking for), a key (what it offers) and a value (what it hands over). Relevance is the dot product of one token's query with every key. A softmax turns those scores into weights that sum to 1. The output is the weighted average of the values, which is added back onto the token.

Q = X·WQ   K = X·WK   V = X·WV
S = Q·Kᵀ / √dhead   # every query vs every key
S = S + mask   # −∞ where not allowed (time layers)
A = softmax(S) row-wise   # each row sums to 1
O = A·V   # weighted average of values
X ← X + gate ⊙ (O·WO)   # residual add

3 · Many heads, fewer keys (multi-head + GQA)

One head can only look for one kind of relevance at a time. So MIRA splits each token's 4096 numbers into 32 heads of 128. Each head has its own slice of WQ, WK, WV and computes its own attention pattern, like heads 1 and 2 above. The 32 outputs are concatenated back to 4096 numbers and mixed by the output matrix WO.

Grouped-query attention (GQA): MIRA keeps 32 query heads but only 8 key/value heads. Each group of 4 query heads shares one key and one value. The queries still look for different things, but there are 4× fewer keys and values to compute and, crucially, to store in the KV cache while streaming.

4 · Where am I? Rotary position embedding (RoPE)

The dot product q·k knows nothing about where tokens are. MIRA adds position by rotating queries and keys before the dot product: a token at position m has pairs of its numbers rotated by an angle proportional to m.

Rotating q by angle m·θ and k by n·θ changes their dot product only by the difference (m − n)·θ. So attention sees relative offsets ("two cells to the left", "0.3 s earlier"), never absolute ones. MIRA uses this in three directions: row and column inside the grid (spatial RoPE), and time in seconds (temporal RoPE).

Because nothing is tied to absolute positions, the same weights work on a 9-row single-player grid and on the 36-row four-player grid. That is how the multiplayer model is warm-started from the single-player one.

7 · Many attention layers, one machine

"Attention" isn't one thing in MIRA. Three separate networks use it, each for a different job. Inside the world model, 32 attention layers take turns on the same tokens. This section shows where they all sit and how information passes between them.

7b · How the layers pass information along

The residual stream is a shared notebook. Every token carries one vector of 4096 numbers from the bottom of the stack to the top. No layer replaces it; each one reads the current notebook of the tokens it attends to and adds a note:

xfinal = xembed + Δspace,1 + Δtime,1 + ΔMLP,1 + … + Δspace,16 + Δtime,16 + ΔMLP,16

So layers affect each other only through what they write into the notebook. What layer 5 adds is part of the input for layers 6 to 16, in every token that later attends to it.

Space and time layers take turns moving information:

  • a space layer moves information sideways: to any cell of the same frame, in any player's view;
  • a time layer moves it forward in time: to the same cell in later frames (never backwards).

Neither can do the other's job alone. But one space + one time layer together can bring information from any cell of any earlier frame to any cell of the new frame (two hops: sideways, then forward, or forward, then sideways). Try it in the demo →

7c · Same depth, different moments: why the KV cache works

While streaming, only the newest frame runs through the 16 blocks. When its token reaches the time layer of block ℓ, it attends to the past frames' block-ℓ keys and values. Those were computed and stored back when those frames were the newest one.

That's allowed only because time attention is causal. A past frame's notebook at block ℓ never depends on anything that came after it, so it never needs updating, and caching is exact. If a time layer could look at the future, every new frame would force the whole past to be recomputed.

Each denoising pass runs the whole stack once: 16 × (space → time → MLP) for the new frame's 576 tokens. A tick runs 1–2 passes. The final clean frame's keys and values are what get stored for the next ticks.

7d · What the layers end up specialising in

Nobody assigns roles to layers; they emerge in training. What the paper shows:

  • Cross-view matching (a car token in one view attending to the same car in the other views; the ball; the shared clock) is clearly visible when attention is averaged over layers 4–7 of the multiplayer model (Fig. 17), the middle of the stack.
  • The game-state probe reads ball and car positions, rotations and velocities from the last layer's activations (Section 6.2). By the top of the stack the notebook holds a physics-level description of the scene, and it gets more accurate with model size (Fig. 16).

A common pattern in transformers generally, though the paper doesn't analyse layer by layer: early layers tend to handle local, low-level features; middle layers match and combine things (here, across views and frames); late layers produce what the output head needs (here, the velocity that denoises the next latent).

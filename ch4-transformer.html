Inside the transformer: tokens, space-time attention and AdaLN

The world model is a 5B-parameter diffusion transformer. Each forward pass takes the noisy next latent plus the past latents, the players' keys and the noise level τ, and outputs the flow velocity from Chapter 02. This chapter opens it up. You'll see how a latent becomes tokens, how attention is split into "space" and "time" to make it affordable, and how keyboard presses steer every layer.

1 · From latents to tokens

Each latent cell (32 numbers, covering 32×32 pixels) is linearly embedded into one token. Patch size is 1, so one cell is one token. The four players' 9×16 grids are stacked along the height into a single 36×16 grid. That gives 576 tokens per latent frame, and the context window holds 20 frames (2 s at 10 Hz).

Positions are encoded with factorised RoPE: 2-D rotary embeddings across the grid and a separate temporal rotary embedding indexed in seconds. Rotary embeddings encode only relative offsets, so no weights are tied to a grid size. That is why a single-player model (9×16 grid) can be warm-started into the 4-player model (36×16 grid) with the exact same weights.

Space layer = consistency Every token sees every other token of the same frame, across all four players' views. This is where "the ball in P1's view" can agree with "the ball in P3's view". The paper shows a P1-car token attending to that same car in the other views (Fig. 17).
Time layer = memory & motion Each token looks only at the same grid cell in earlier frames (causal: never the future). This is how motion and persistence flow forward. It is also why context length limits memory: an off-screen car older than the window is gone (Ch. 07).

3 · How keys steer every layer: AdaLN

Actions are not tokens. Each player's 9 keys are embedded by a per-player network. The four embeddings are concatenated in a fixed player order (the same order as the view tiling) and summed with the embedding of the noise level τ into one conditioning vector c. From c, each block predicts a scale γ and shift β, and every token's normalised features are modulated as (1 + γ)·LN(x) + β. Toggle keys below and watch c, γ, β and a token's features change.

Notice that pressing P1's W changes γ and β for every token, including P4's HUD token. The conditioning is broadcast to all positions. Nothing tells the model which key belongs to which view: it has to learn that P1's keys move P1's camera and P1's car as seen by others, and leave the sky alone. The "absent" checkbox swaps in the learned absent token used for action dropout (Ch. 05). Actions are logged at 20 fps and latents run at 10 Hz, so a learned linear layer also pools the two action frames that fall inside each latent step.
